## 一句话判断
Agent 竞争正在从“尽可能多烧 Token”转向“让每个 Token 产生可验证价值”：更可持续的形态可能是==本地开源模型处理高频常规任务、前沿模型处理高难任务，再用 Skills、记忆和多 Agent 协作沉淀复用能力==。

## 核心观点
1. **Token 使用量不是生产力指标，真正的问题是价值能否覆盖推理成本。** `事实 + 嘉宾判断`
   - Agent 会反复规划、调用工具和修改结果，Token 消耗远高于普通聊天；若组织只奖励使用量，就容易把“调用很多”误当成“产出很多”。
   - 节目以 Token Maxing 热潮、企业预算压力为背景。Uber 确实在 2026 年前四个月耗尽年度 AI 编程预算，随后对部分工具设置每人每月 1,500 美元上限；但这只能证明预算预测与治理失灵，不能单独证明 AI 没有生产力。[Los Angeles Times 报道](https://www.latimes.com/business/story/2026-06-02/uber-caps-staff-use-of-ai-coding-tools-after-blowing-its-budget)

2. **可持续的模型策略不是“永远用最强模型”，而是按任务价值进行分层路由。** `嘉宾观点 + 个人经验`
   - 日常检索、整理和格式转换不一定需要最昂贵的前沿模型；高难推理、关键决策和低容错任务才值得升级模型。
   - 黄东旭在节目中自述曾高额使用前沿模型，后来转向“本地开源底座 + 前沿模型”的组合。其“本地每天只需约 1 美元电费”是特定硬件、模型和使用方式下的个人账，==不能普遍外推==。

3. **Skills 的意义，是把偶然成功的 Agent 轨迹变成可以重复调用的程序性知识。** `嘉宾观点 + 可验证产品机制`
   - 单次对话会遗忘，长提示词又持续占用上下文；将稳定流程保存成 Skill，可按需加载、持续修订，并把“如何做”与“记住什么”分开。
   - 节目将 Hermes 的重要变化概括为沉淀成功经验。Hermes 官方文档也把 Skill 定义为按需加载的程序性知识，并与每轮注入的事实性 Memory 区分；不过“能自动生成 Skill”不等于生成的流程一定正确，仍需测试、权限控制和版本管理。[Hermes Skills 官方文档](https://github.com/hermes-agent-org/hermes/blob/main/website/docs/guides/work-with-skills.md)

4. **多 Agent 的“涌现”首先是一种计算扩展——并行增加搜索宽度、上下文和 Token，而不是凭空产生智能。** `嘉宾观点 + 外部实测`
   - 当任务可以拆成彼此相对独立的方向时，多个 Agent 能并行搜索，再由主 Agent 汇总；但强依赖、共享上下文密集的任务会产生协调成本。
   - Anthropic 的内部研究评测中，多 Agent 研究系统比单 Agent 高 90.2%，但多 Agent 使用量约为普通聊天的 15 倍；该结果来自特定研究型任务与自家模型，==不能直接推广到所有编码或办公任务==。[Anthropic 工程报告](https://www.anthropic.com/engineering/multi-agent-research-system)

5. **Agent 间通信会增加 Token 需求，但协议成熟度与应用成熟度必须分开判断。** `预测 + 已发生的基础设施进展`
   - 如果不同组织的 Agent 能发现彼此能力、委派长任务并交换产物，单个请求可能扩展成整个 Agent 网络；与此同时，认证、权限、可观测性、失败恢复和成本归属都会变难。
   - Google 的 A2A 已定义 Agent Card、任务生命周期、消息和产物等机制，并支持长任务与多模态。但“已有开放协议”只证明互操作基础正在形成，==不证明大规模 A2A 网络已经可靠或经济可行==。[Google A2A 官方介绍](https://developers.googleblog.com/a2a-a-new-era-of-agent-interoperability/)

6. **Agent 创业的护城河不能只是一个容易被基础模型吸收的功能。** `嘉宾观点`
   - 模型持续增强会快速商品化通用写作、摘要和简单工作流；更稳固的价值来自专有数据、深度业务集成、可信评测、权限与审计、持续反馈闭环，以及真实客户愿意付费的任务结果。
   - 节目嘉宾更看好 ToB 与基础设施，并提醒不要做容易被大模型“碾压”的应用。这是创业判断而非定律；模型厂商也可能进入基础设施与企业工作流，因此仍需用客户需求和单位经济验证。

7. **“IQ 测试超人类，所以 AGI 奇点已到来”是强观点，不是已被证明的事实。** `嘉宾观点 + 预测/推测`
   - 静态测验、代码 benchmark 或某类智力测试，无法充分衡量长期自主性、现实常识、可靠性、社会协作与跨环境迁移。
   - METR 的研究显示前沿 Agent 能完成的任务时间跨度在增长，但其指标只针对一组可自动验证的软件、机器学习和安全任务；METR 还明确提示，超过 16 小时的测量目前不可靠。因此它支持“能力快速进步”，但不足以验证“AGI 已经到来”。[METR Task-Completion Time Horizons](https://metr.org/time-horizons/)

## 外部补充
- **自托管并非天然更便宜。** OECD 2026 的示例测算认为：低于每月 1 亿 Token 的小负载，自建的经济优势并不明显；约 10 亿 Token/月时，示例盈亏平衡需要约 30 个月；更大负载才可能迅速摊薄固定成本。因此选择本地模型应计算硬件折旧、利用率、电费、维护、工程人力和模型能力损失，而不能只算电费。[OECD《Benefits of AI openness》](https://www.oecd.org/content/dam/oecd/en/publications/reports/2026/05/benefits-of-ai-openness_40eaff39/746e8c9a-en.pdf)
- **“Meta 已经给员工设置 Token 上限”需要校正。** 2026 年 7 月的公开采访中，Adam Mosseri 表示未来一两年可能需要按工程师设置上限，但当时 Meta 尚未实施统一员工 Token 硬上限；公司已关闭鼓励消耗的内部排行榜。节目若将其表述为已全面设限，属于过度简化。[TechCrunch](https://techcrunch.com/2026/07/14/metas-adam-mosseri-says-ai-token-budgets-could-soon-be-capped-per-engineer/)
- **最值得借鉴的工程原则是“按价值扩展计算”。** 简单任务使用单 Agent 或便宜模型；可并行且价值高的任务才启用多 Agent；失败代价高的步骤升级到强模型或人工复核。核心指标应是每次成功任务成本、返工率、延迟和业务价值，而不是总 Token 数。

## 值得思考
- 如何定义可执行的 **Value per Token**：每完成一个可信任务的总成本，而不是单纯 API 单价？
- 本地模型、便宜 API 与前沿模型之间，路由器应根据难度、隐私、延迟还是失败代价决策？
- 哪些任务真正可以并行拆解，哪些任务会被 Agent 间协调和上下文同步拖垮？
- Skill 如何进行回归测试、权限审查、版本控制和过期淘汰，避免“错误经验永久化”？
- 当模型能力继续上移时，产品真正不可替代的是 UI、工作流、数据、分发，还是责任承担？
- 如果新岗位也不断被自动化，人类的比较优势是否会转向问题定义、价值判断、责任与关系建立？这个问题重要，但节目给出的答案仍是开放的。

## 关键概念
- **Token Maxing / Token Minimizing**：从以消耗量彰显 AI 投入，转向约束成本、衡量产出。
- **Value per Token**：单位 Token 或单位推理成本创造的可验证任务价值。
- **Model Routing**：按任务难度、成本、隐私与风险，在本地模型和前沿模型间选择。
- **Skill / Procedural Memory**：可按需加载、复用和更新的任务执行流程。
- **Multi-Agent Orchestration**：主 Agent 拆解任务、多个 Agent 并行执行并汇总。
- **A2A（Agent2Agent）**：让不同框架或厂商的 Agent 发现能力、通信和管理任务的协议。
- **Task-Completion Time Horizon**：以人类专家完成任务所需时长衡量 Agent 可可靠处理的任务难度。

## 需要记住的五件事
1. **不要优化 Token 消耗量，要优化每个成功任务的价值、成本和可靠性。**
2. **本地模型 + 前沿模型是有吸引力的组合，但是否省钱取决于负载规模、利用率和失败成本。**
3. **Skill 的长期价值在于把一次成功变成可测试、可维护、可复用的程序性知识。**
4. **多 Agent 可以用更多 Token 换取搜索宽度，但只适合高价值、可并行任务；15 倍消耗不是免费的智能。**
5. **能力增长、协议成熟和 AGI 到来是三个不同命题；任何“奇点已至”的判断都需要更广泛的可靠性证据。**
